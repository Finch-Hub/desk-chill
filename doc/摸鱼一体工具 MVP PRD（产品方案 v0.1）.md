# 摸鱼一体工具 MVP PRD（产品方案 v0\.1）

# 决策摘要

**建议：进入 P0（个人 MVP）研发。**以「贴边收起窗口引擎」为差异化核心，P0 只做四件套——本地 TXT/PDF 阅读、贴边收起、WebView 浏览、老板键；明确不做书源聚合、云同步、对抗企业审计、移动端。前置动作：先对照试用现有工具 2 周，若已满足需求则停止自研。

**依据：**① 调研报告确认需求真实但透明消隐路线同质化，「驻留式贴边收起＋阅读/浏览一体」是稀缺位（产品分析报告 F1—F6）；② 按用户最新指令，采用主流前端方案 Electron＋Vue3，兼容性与可迁移性优先，个人自研技术成本低；③ 企业审计是硬边界，「高隐蔽」定位只对防人眼成立，因此不做任何绕过企业监控的功能。

**关键取舍：**P0 用「驻留式贴边收起」而非「透明消隐」，换来实现简单、稳定可靠与 QQ 式用户心智；代价是隐蔽强度略低于透明伪装，接受此取舍进入本期。

**本期范围：**P0 四件套构成「摸鱼」最小闭环；P1/P2 后置；Non\-goals 见「范围」章节。本文档为研发可执行的 PRD，若开发环境或依赖无法确认，按「待确认事项」的暂定决定执行。

# 背景与目标

本方案基于《摸鱼一体工具（阅读器＋轻量浏览器＋贴边收起）产品分析报告》形成（[查看调研报告](https://feishu.doubao.com/docx/NSOvd8JEmoz3ifxwsMlcH8IDnne)）。**目标：**为办公摸鱼场景的 Windows 用户提供一个单窗口「阅读＋浏览＋高隐蔽」工具，使个人日常摸鱼能完全替换「浏览器＋微信读书＋手动隐藏」的现状组合，且切换成本更低、被注意次数不高于现状。

# 技术选型（按最新指令修订）

**变更说明：**原调研报告基于「轻量优先」排除 Electron；用户最新指令要求「考虑兼容性与可迁移性，采用主流前端方案」，本修订以新指令为准。**结论：主选 Electron＋Vue 3＋TypeScript＋Vite；Tauri 2 为轻量备选。**

**为什么是 Electron：**① 兼容性——自带 Chromium 内核，不依赖目标机器是否安装 WebView2 Runtime，企业精简或锁定系统也能直接运行，渲染行为跨机器一致；② 可迁移性——全部 UI 是标准 Web 技术（Vue3），未来可抽成 Web/PWA 版本或更换 Tauri 壳，核心代码不锁死 Windows；③ 主流度——桌面壳市场占有率最高、文档与社区最全，个人开发遇问题最易检索；④ 技能匹配——已有 Vue/JS 全栈基础，无需新学 C\#/Rust。

**代价（明示）：**内存占用高于原生方案（Chromium 多进程常驻约 150—300MB，经验值需实测）；安装包约 70—120MB；隐藏至托盘后进程仍在后台运行。对个人工具可接受，若实测不可接受按「何时切换 Tauri 2」规则处理。

**关键功能落地：**贴边收起＝无边框窗口（frame:false）＋屏幕边缘检测＋位置/尺寸动画；全局老板键＝globalShortcut；托盘＝Tray；内置网页＝WebContentsView 嵌入主窗口，与渲染进程共享会话，登录态与视频播放天然支持；本地文件读写＝Node fs。

```js
const { app, BrowserWindow, globalShortcut, Tray, Menu } = require('electron');

// 1) 无边框窗口：frame:false 是贴边/伪装形态的基础
// 2) 贴边收起：轮询 screen.getCursorScreenPoint()，主边缘距屏幕边缘 <=8px 且鼠标已移出窗口 -> 收起为 4px 边条
// 3) 老板键：globalShortcut.register('F8', toggleTray)；返回 false 即热键被占用，提示改键
// 4) 托盘：new Tray(icon) + Menu（显示主窗口 / 退出）；退出前保存全部阅读进度并确认
// 5) 内置网页：new WebContentsView({ webPreferences:{ partition:'persist:moyu' } }) 保留登录态
// 调试思路：electron . 直接运行；贴边几何问题用日志输出 window bounds 与鼠标坐标对照，勿凭感觉调参数
```

**架构与可迁移性设计：**三层解耦——渲染进程（Vue3 UI）不直接调用 Node，一切系统能力经 preload 暴露的 IPC 桥接；主进程（窗口引擎/热键/托盘/文件读写）可整体替换为 Tauri 壳；UI 层未来可发布为 Web/PWA。坚持此边界，技术壳的更换成本最低。

# 核心需求规格

## FR\-1 本地阅读器（TXT/PDF）

**触发与输入：**窗口内点击「打开文件」或把 \.txt/\.pdf 文件拖入窗口。**系统行为：**TXT 按编码检测（UTF\-8/GBK/UTF\-16）解码，识别失败时弹出编码选择；PDF 走 P0 选定的渲染方案（见待确认事项 2）；阅读设置（字号、行距、背景色、翻页方式）即时生效并保存；每本书关闭时自动保存进度，启动时恢复到上次位置。

**异常与恢复：**超大文件（约 50MB 以上 TXT）采用惰性/分段加载，避免启动卡死；损坏或加密 PDF 显示明确错误提示，程序不退出；编码未知时提供选择，默认不乱码。

**验收：**成功——打开 5MB UTF\-8 TXT，首屏可读且滚动流畅（自测基线，非对外承诺）；关闭重开恢复到上次进度与页。**失败/边界：**GBK 编码 TXT 不乱码（自动识别或手动选择后正常显示）；损坏 PDF 报错且程序不崩溃。

## FR\-2 贴边收起窗口引擎（核心差异化）

**行为规格（四态状态机）：**「正常展开」→ 拖动窗口使主边缘贴近屏幕边缘（间距 ≤8px，初始值）并松开 →「贴边收起」为露出 4px（初始值）的边条；「贴边收起」→ 鼠标移入边条热区或点击边条 →「正常展开」并恢复到收起前的位置与尺寸（动画 ≤300ms，初始值）；任意状态按老板键 →「托盘隐藏」；再按热键或点击托盘图标 → 恢复到最后状态；托盘菜单「退出」需用户确认后 →「已退出」。鼠标移开边条后保持收起，不自动展开、不自动退出。

**设置项：**贴边方向（左/右/上/下）；是否启用「移出即收起」（默认关闭，按 QQ 行为保持收起）；恢复位置记忆。

**异常与恢复：**多显示器时只在当前工作区边缘收起；边条自动避开任务栏区域；与其他置顶窗口重叠时边条仍可点击；收起期间阅读进度不中断。

**验收：**成功——拖到屏幕左边缘松开，窗口收起为露出 4px 的边条；点击边条，窗口在 500ms 内展开回收起前位置与尺寸。**失败/边界：**边条落在任务栏区域时仍可点击展开；收起状态下按老板键能进入托盘隐藏；移出边条后保持收起不误展开。

## FR\-3 内置浏览器（Electron Chromium）

**触发与输入：**地址栏输入 URL 或关键词（回车后按系统默认搜索引擎检索）；点击常用站点快捷入口。**系统行为：**Electron 内置 Chromium（WebContentsView）渲染；前进/后退/刷新；页面加载状态提示；会话保留（登录态在窗口生命周期内保持，如小红书扫码登录后刷新仍有效）。

**异常与恢复：**断网、证书错误显示可读错误页而非白屏；借助 Chromium 多进程架构隔离网页进程，单页面崩溃自动刷新或提示重试，不影响阅读器与主进程；P0 不拦截弹窗与下载，按 Chromium 默认行为处理。

**验收：**成功——访问 bilibili\.com 正常加载并可播放；小红书网页版扫码登录后刷新页面仍保持登录。**失败/边界：**断网访问显示可读错误提示；页面崩溃后程序主体不退出。

## FR\-4 全局老板键与托盘

**触发与输入：**全局热键（默认 F8，支持自定义组合键）。**系统行为：**按下后窗口与任务栏入口消失，仅保留托盘图标；再按恢复到最后状态（展开或贴边收起）；托盘菜单提供「显示主窗口」「退出」；退出前保存全部阅读进度并弹确认框。

**异常与恢复：**热键被其他应用占用时，启动阶段检测并提示改键，不静默失败；隐藏期间页面加载等事件不弹窗打断；确认退出后所有进度已保存。

**验收：**成功——任意前台应用下按 F8，本窗口消失且任务栏无入口；再按 F8，恢复到隐藏前状态。**失败/边界：**热键冲突时给出改键提示；托盘隐藏状态下退出需二次确认，且进度已保存。

# 依赖与风险

**技术依赖：**Electron（自带 Chromium，Win10/11 全兼容，不依赖系统 WebView2 Runtime；Win7 仅可选用已停止安全更新的旧版 Electron，不建议）；Node\.js 生态与 Vue3/Vite 工具链；贴边、热键、托盘、置顶全部使用 Electron 内置 API；PDF 渲染方案待技术 spike 确认（见待确认事项 2）。

**产品风险：**贴边误触或展开延迟 → 通过 4px/300ms 初始参数实测校准；Electron 内存占用高于原生（约 150—300MB 常驻）→ P0 验证期实测，若不可接受按「何时切换 Tauri 2」规则换壳（UI 层复用）；企业环境禁止安装第三方软件 → 触发停止条件；竞品快速跟进贴边功能 → 个人工具无商业压力，不改变决策；小红书等网页版登录与反爬限制 → FR\-3 以「扫码登录后保持会话」为验收边界，不做绕过。

# 用户流程

**核心结论：**主流程闭环为「启动→续读/导入→阅读→贴边或隐藏→恢复」；摸鱼切换流程是差异化验证的关键，全部切换以「不高于 2 步」为设计目标（Phase 1 证据门）。

## 三条核心流程

|**流程**|**触发**|**主步骤**|**关键状态**|**异常出口 / 支撑事件**|
|---|---|---|---|---|
|**启动并续读**|双击启动；拖入 \.txt/\.pdf|加载书库→自动打开最近阅读或解析导入→翻页→节流保存进度|阅读视图 / 正常展开|损坏 PDF、编码未知 → toast/模态选择；book\_open、book\_import\_\*、book\_progress|

|**网页浏览**|地址栏输入；点快捷站点|WebContentsView 加载→浏览→扫码登录→返回阅读（会话保留）|浏览器视图|断网/证书错误页、页面崩溃提示刷新；browse\_nav/error、page\_crash|

**四视图线框：**阅读、浏览器、书库、设置；标注关键字段、状态位与交互位置。低保真仅定结构与交互位，视觉风格（配色/字体）后置，P0 直接按此结构实现。

# 状态与异常流程

## 状态定义

|**对象**|**状态集**|**迁移触发**|**异常去向**|
|---|---|---|---|
|窗口|NORMAL（展开，含阅读/浏览）／DOCKED（贴边收起）／TRAY（托盘隐藏）／EXITING|拖动贴边、滑过/点击边条、F8、托盘退出|贴边误触→保持 DOCKED 不误展开|

# 埋点需求

**原则：**全部事件仅本地记录（events\.log），不上传网络——与「不做对抗审计、隐私合规」边界一致；事件服务 Phase 1 证据门与贴边参数校准；日志按日轮转、保留 30 天，设置内可导出。

|**事件**|**触发时机**|**关键属性**|**用途**|
|---|---|---|---|
|app\_launch|应用启动|ts、version|使用频次|
|app\_quit|退出确认通过|ts、sessionDuration|使用时长|
|book\_open|打开书/续读|bookId、format、size|阅读行为|
|book\_progress|进度保存（节流 1s）|bookId、pos、percent|续读与证据门|
|book\_import\_ok / fail|导入结果|format、size、errType|导入质量|
|book\_import\_encoding|编码未知触发模态选择|format、chosen|编码处理质量|
|book\_missing|打开失败（路径缺失）|bookId|数据健康|
|dock\_dock|收成边条|edge|贴边使用|
|dock\_undock|展开|edge、duration|顺手度，校准 dockAnim/dockPeek|
|boss\_hide / boss\_restore|老板键隐藏/恢复|ts、fromState|隐蔽行为链路|
|bosskey\_conflict|启动热键注册冲突|key|热键健康|
|quit\_blocked|退出时保存失败被阻止|reason|数据安全|
|browse\_nav|页面导航|urlDomain、isQuick|浏览行为|
|browse\_error|加载错误|urlDomain、errType|稳定性|
|page\_crash|页面崩溃|urlDomain|稳定性|
|settings\_change|设置保存|key、value|参数校准|

**证据门映射：**连续 5 个工作日使用＝app\_launch＋book\_open 按日聚合；切换动作不高于 2 步＝boss\_hide→boss\_restore→dock\_\* 链路步数统计；未被注意次数＝用户手动记录（无自动事件，靠对照期自记）。
